## 2. 설계

### 2-1. 상단바 (지적 1·2)
- 칩 숨김 우선순위: 노선 칩(`.chip.root`)과 도움/설정을 **절대 숨기지 않는다**. 줄이는 순서는 `정찰·파견 → 물가 → 연합견제 문구 약어 → 국책 칩 약어 → 녹봉 보조 숫자 → 병력/군량 보조`, 마지막에도 모자라면 국책 칩을 아이콘화.
- 도움/설정: 같은 크기·같은 테두리(둘 다 일반 `b s`, 설정 금색 제거 또는 둘 다 금색). `sticky`·`box-shadow` 제거, 상단바 오른쪽 끝에 flex로 나란히(`margin-left:auto; gap:6px; flex:none`). 칩이 넘치면 가운데 영역(`.sp`)만 줄어들고 가로 스크롤 대신 숨김 우선순위로 처리.
- 상단바 높이(30px)는 유지하고, 터치 대상은 44px 규칙(CSS 13926~)과 충돌하지 않게 히트 영역만 확장.

### 2-2. 전체화면·가로 복귀 (지적 3)
- `visibilitychange`(visible)·`fullscreenchange`·`pageshow`에서 ① `s7RotSync`·`s7Fit` 재계산 ② 터치 기기이고 `fullscreenElement`가 없으면 다음 탭에서 전체화면 재시도(`done` 플래그를 복귀 때 초기화).
- 전체화면이 안 되는 브라우저(삼성 인터넷이 거부하는 경우)를 위해 화면 왼쪽 아래에 작은 `전체화면` 단추를 띄운다(전체화면이면 숨김). 사용자 제스처에서만 호출되므로 거부 확률이 가장 낮다.
- `s7RotSync`는 body 크기를 `innerWidth/innerHeight`가 아니라 `visualViewport`(있으면) 기준으로 계산하고, 값이 바뀌면 `left`도 같이 갱신. 안전영역(`env(safe-area-inset-*)`) 반영.
- 검증은 크롬 DevTools 기기 에뮬레이션(삼성 인터넷은 불가)과 사용자 실기 확인으로 나눈다. 실기 확인 항목은 문서 §5.

### 2-3. 시트 3종류 (지적 4·5·7)
가로 모드의 하단 시트 하나(고정 220px)를 용도별 3종으로 나눈다.

| 종류 | 용도 | 모양 | 예 |
|---|---|---|---|
| 확인형 | 내용이 짧고 실행 하나 | 가운데 작은 카드(폭 360px, 높이 자동). 본문 1~3줄 + 버튼 2개 | 이번 달 끝내기, 세율 변경 확인, 단발 실행 |
| 목록형 | 장수·도시·품목을 고름 | 좌(목록)·우(선택 요약+실행 버튼) 분할, 높이 `min(70vh, 내용)`, 우측이 비면 요약·예상 결과로 채움 | 징병·훈련·수련·이동·포상 |
| 정보형 | 긴 설명·그래프·표 | 전체 폭, 높이 `min(78vh, 내용)`, 내부 스크롤 한 곳만. 가로에서는 좌 요약 / 우 본문 | 연간 보고서, 노선 상세, 교역 시세 |

- 이번 달 끝내기: 경고가 없으면 시트 없이 **상단 확인 카드**("이번 달을 끝냅니다 — 남은 장수 0명, 금 부족 도시 없음" + `끝낸다`/`취소`). 경고가 있으면 같은 카드에 경고를 붙인다. 아래 별도 버튼 줄 없음.
- 높이는 고정 220px를 버리고 `max-height` 상한만 두며, 이미지는 `max-height:30vh; object-fit:contain`.
- 분할 시 한쪽이 거의 비는 경우(`dk.two`에서 한쪽 행 수 ≤ 2)는 분할을 풀고 목록형 단일 열로.

### 2-4. 교역 (지적 6)
- 교역 커맨드의 1단계는 **명령만** 둔다: `상거래 · 시세표 · 수송 · 학습 · 친교`(현 "해외 교역" 하위) 와 노선 전용 `갈래 행동`, `고가품 판매`.
- "교역 효과" 버튼 묶음(`trFxHtml`)을 명령 목록에서 분리해 각각 이름 있는 명령으로 만든다. 설명 문장(열린 품목·다음 개방)은 시트 아래 한 줄 또는 정보형 `자세히`로.
- 고가품: 이름을 `고가품 판매`로 바꾸고 버튼에 **결과를 보여준다** — `이번 달 1/2회 · 예상 순이익 금 N(이익률 x%, 포화 ×y)`. 잠긴 경우 `교역도 40 이상 필요(현재 N)`. 등급(1~3)은 이익률 변화로만 설명.
- 설계상 열린 문제(결정 필요): 고가품이 금만 늘리는 단순 효과로 남을지, 뿌리별 갈래(강병/상략/경륜/덕화)와 엮을지. 이 문서에서는 **표시 개선만** 다루고 효과 조정은 별도 설계로 미룬다.

### 2-5. 장수 없는 명령의 틀 (지적 7)
- 판정 규칙: 명령이 장수 배정(능력·직무)을 필요로 하지 않으면 목록형 대신 확인형. 아래 표는 전수 조사 후 확정.

### 2-6. 연간 보고서 (지적 8)
- 정보형 시트로 이전. 가로: 좌 1/3 요약 수치(수입·지출·흑자·전년비), 우 2/3 그래프 한 장 + 그래프 전환 탭(재정·인구/병력·인재·통치). 세로(회전)에서는 탭 위, 그래프 아래.
- 그래프 높이는 `min(40vh, 240px)`로 상한, 한 번에 한 장만 렌더(숨은 탭은 렌더 안 함 → 시트 높이 감소).
- 겹겹이 덧붙은 보고서 정의(10457·10483·10524)는 정리 대상. 정리 시 `docs/코드지도.md`에 죽은 정의 삭제 기록.

## 3. 영향 범위와 위험
- 시트 3종 도입은 `renderSheet` 래퍼가 5개 이상 겹쳐 있어(13652~·13866~·14013 등) 변경 위험이 크다. 래퍼 순서를 `grep -n "renderSheet = function"`로 먼저 표로 만든다.
- 전투(V4)·교역 수치·내정 수식은 건드리지 않는다. 전투 재측정(`battle_sim`) 해당 없음.
- 교역 재구성은 `ACT.trFx`·`trFxDo`의 호출 경로를 유지한 채 UI 진입점만 바꾼다.

## 4. 전수 조사 필요 목록 (빌드 전)
- `openMulti` 사용처별로 "장수 선택이 실제로 필요한가": 징병·훈련·수련·교습·수색·이동·포상·유학·인재 정찰 (모두 현재 `openMulti`). 각 명령의 `run`이 장수 인자를 쓰는지 확인해 표로 채운다. **현재는 미조사.**
- 장수 인자 없는 시트: 세율, 시설 건설, 교역 갈래, 이번 달 끝내기 등(후보, 미확인).

## 5. 사용자 실기 확인 항목(빌드 후)
- 삼성 인터넷 가로: 앱을 나갔다 돌아온 뒤 주소창 유무·가로 쏠림.
- 상단바: 불만·연합견제·정찰이 모두 붙은 상태에서 노선 칩·도움·설정이 보이는지.
- 시트 3종: 이번 달 끝내기, 징병(목록형), 교역, 연간 보고서(정보형)가 각각 한 화면(또는 한 스크롤)에 들어오는지.
