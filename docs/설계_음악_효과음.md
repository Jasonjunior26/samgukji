## (b) 업그레이드안 — 화려하게

방침: 새 엔진을 만들지 않고 **v87 레이어 위에 얹는다.** 곡 데이터(`SONGS3` 문자열)와 악기 함수는 유지, 빠진 층을 채운다.

1. **레이어 4단 + 점진 진입**: 리듬(북·징·목탁·바라) / 베이스(낮은 고쟁·대금풍 저음, 근음·5도) / 화성(패드 + 쟁 분산화음) / 선율(이호·적·비파 + 대선율 응답). 128마디 순환 중 편곡 단계마다 층을 하나씩 더하고(마디 0~15 선율+패드, 16~31 베이스, 32~63 리듬 추가, 64~ 대선율·장식음) 마지막 16마디는 절정(전 층, 징·큰북 롤) 후 처음으로 돌아가게 한다.
2. **삼국지풍 음색 보강**: 비파 트레몰로(빠른 반복 뜯기), 고쟁 글리산도(스쳐 올리기), 적 플러터·포르타멘토, 큰북 '둥-둥-두두둥' 장단(진양·중모리 느낌 변주), 징 여운 길게, 나각(소라 뿔) 신호음 전투 도입. 오음계(궁상각치우)는 유지하되 전환부에 변치(4도 올림)를 한 음 섞어 색을 줌.
3. **장면별 곡 구성**: 현행 8곡에 더해 title(웅장한 도입 + 징), 승리(펜타토닉 팡파르 8초)·패배(느린 이호 하강 8초)·즉위·서거·외교(차분한 고쟁)·계략(낮은 북 + 비파 단음)을 **짧은 변주 곡/징글**로 추가. 전부 새 곡을 쓰지 않고 `SONGS3` 의 같은 주제를 템포·악기·조성만 바꿔 파생(작곡 비용 최소화).
4. **WebAudio 기법**: 마스터 체인 `musicGain → (저역 쉘프 +2dB, 고역 -1dB) → compressor → destination`; 반주는 `StereoPanner` 로 좌우 배치(이미 `panOut`), 리드는 중앙 + 미세 코러스(±6 cent 두 개 오실레이터); 잔향 센드를 악기별로 달리(북 0.15 / 이호 0.4 / 패드 0.6), 공용 `rev2` 1개만 사용; 전투 중에는 로우패스 슬로우 스윕으로 장면 전환 연출; 필터 포락 `exponentialRamp` 로 클릭 노이즈 방지.
5. **곡 길이·루프**: 현행 128마디(템포 66~140 → 약 3~7분). 유지. 장면 전환은 현행처럼 0.25초 페이드아웃 후 재시작이나, 계절 전환은 **교차 페이드**(1.5초)로 개선.
6. **CPU 부담 상한(제안 목표, 미측정):** 동시 활성 오실레이터/소스 **40개 이하**, 박자당 신규 노드 **60개 이하**, 잔향 컨볼버 **2개 이하**(공용), 선스케줄 0.3초 유지, 탭 숨김 시 `suspend` 유지. 층은 "품질 3단계(낮음=리듬+선율+패드 / 보통 / 높음=전체)"로 나누고 **기본 보통, 설정에서 변경.** 끊김 감지(`ctx.currentTime` 지연 > 80ms 연속 3회)시 한 단계 자동 하향. 모든 수치는 구현 후 실측으로 확정(Galaxy S22 실기기 **미확인**).

## (c) 효과음 설계

**공통:** 모두 `SND.sfxGain` 경유, 합성 직접 생성(파일 없음), 새 `SFXUI` 객체로 `SFX` 와 분리, `SND.sfxOn` 토글에 연동. 모바일 잠금 때문에 오디오 컨텍스트가 없으면 조용히 생략(오류 없음).

### 커맨드 클릭음 (단추를 누른 즉시, 100ms 이하)
현행 `CMD_SFX` 는 결과음(성공/실패 후)이라 유지하고, **누르는 순간의 짧은 클릭**을 별도로 추가한다. 종류 5종:

| 종류 | 대상 | 음색 | 길이 |
|---|---|---|---|
| tick 기본 | 일반 단추·시트 | 목탁풍 사각파 1100Hz 짧게 + 하이패스 노이즈 | 45ms |
| 내정 | 개발·건설·교역 | 쟁 한 음(오음 중 궁) 뜯기, 감쇠 빠름 | 80ms |
| 군사 | 징병·훈련·출진 | 낮은 북 'ㅌ' 한 번(사인 160→70Hz 하강) | 70ms |
| 인사 | 등용·임명·장수 | 맑은 종 한 방(1.5·2.76배음 짧게) | 90ms |
| 취소/닫기 | 뒤로·닫기 | 내리는 두 음(삼각파 -3반음) | 60ms |

**연타 처리:** 종류별 최소 간격 40ms(`ok()` 와 같은 방식) + 전체 동시 발음 4개 상한(초과 시 가장 오래된 게인을 15ms 에 0으로). 같은 음이 겹치지 않게 ±8 cent 랜덤. 클릭음은 현행 결과음(`CMD_SFX`)과 겹치면 결과음 쪽 첫 80ms 를 -4dB 로 낮춰 무뎌지지 않게 한다. 연결은 `pointerdown`(캡처)에서 `data-a` 단추 → 종류 표(`ACT` 이름→종류)로 판별, 표에 없으면 tick. 전투 화면(V4)은 기존 `JSND` 가 맡으므로 생략. 

### 월말 → 새 달 징글 (1~2초)
`ACT.confirmEnd`/`monthlyUpdate` 래퍼 시점(새 달 화면 표시 직후)에 1회. 구성: 징 '쿵~'(0~0.9초 여운) + 쟁 오음 상행 4음 아르페지오(0.1~0.6초) + 바라 한 방. 길이 약 1.4초, 음량은 곡 위에 얹혀도 묻히지 않게 `sfxGain` 의 0.8배.
- **계절 전환 변주(제안):** 같은 달 안에서는 기본형. 계절이 바뀌는 달(3·6·9·11·1월)만 5음으로 늘린 변주 — 봄 적 반짝임, 여름 북 롤 추가, 가을 이호 한 음 하강, 겨울 종 두 번, 1월 폭죽(기존 `sndFirecracker` 재사용). 이 변주가 과하다고 판단되면 모든 달 기본형 하나만.
- 자동 진행·AI 처리 중에는 소리 없음, 빠른 연속 '이번 달 끝내기' 대비 최소 간격 1.2초.

### 설정
기존 `bgmCtl()` 에 이미 "전투 효과음 켜짐/꺼짐" 이 붙어 있음(11236)을 **"효과음"(전투+명령+달 전환)** 으로 개칭하고, 볼륨 3단(작게/보통/크게)을 분리해 `sg_sfxvol` 에 저장. 현행은 효과음 크기가 BGM 크기에 연동(`min(1, vol*1.1+0.2)`)이라 BGM 을 줄이면 효과음도 줄어드는 문제가 있음 → 분리 필요. 클릭음만 따로 끄는 항목 "클릭음"(켜짐/꺼짐)도 둔다(선택).

## (d) 구현 순서와 검증

1. **효과음 먼저** (위험 낮음, 효과 즉시): 클릭 5종 + 월말 징글 + 설정 분리. `SFXUI` 신규 블록 하나만 추가.
2. **믹스·마스터 체인**: 설정 3단계(품질), 쉘프 EQ, 교차 페이드.
3. **레이어 보강**: 베이스·북 장단·대선율을 `songStep` 래퍼에서 추가(기존 곡 데이터 불변).
4. **장면 곡 파생**(승리·패배·외교·계략·즉위·서거).
5. 계절 변주·ambient 다듬기.

**검증 방법**
- **오프라인 렌더 도구 `tools/audio_render.js`(신규 제안):** Node 에서 `OfflineAudioContext` 가 없으므로 (a) `node-web-audio-api` 같은 외부 패키지를 쓰거나(설치 필요 — 사용자 승인 사항), (b) 현재 파이썬 합성 도구(`tools/synth_sfx.py`, `tools/wav_stat.py`)처럼 **효과음 설계 파형을 순수 파이썬으로 먼저 합성해 길이·피크·RMS 측정**한다. 가능성은 (b) 가 확실, (a) 는 미확인. 합격 기준: 클릭 길이 ≤100ms, 피크 ≤ -3 dBFS, 클리핑(|x|≥1) 0 샘플, 징글 1~2초, 연타 시 합성 피크가 단일음 +6dB 이내.
- **헤드리스 Chrome:** 기존 `tools/shot_harness.html?audio=1`·`window.__sfxLog` 방식으로 호출 순서·음소거·연타 간격 확인(소리 자체는 못 들음).
- **노드 수 점검:** `AudioContext` 에 계수 래퍼를 끼워 박자당 생성 노드 수를 로그(헤드리스 가능).
- **실기기(Galaxy S22 삼성 인터넷):** 자동재생 잠금 해제, 백그라운드 복귀, 발열·끊김, 실제 음색 평가는 **미확인** — 빌드 후 사용자가 청취.
- 문서 규칙: 버전업 시 `docs/변화_UI_저장_음악.md` 맨 위 항목, 코드지도 줄 번호 갱신, 전투(`V4.*`) 코드는 안 건드리므로 `battle_sim` 재측정은 "해당 없음".

## (f) 전쟁(전투) 씬 BGM — 추가 조사와 설계

### 원인 (코드 읽기로 확인, 실기기 청취는 미확인)
**재생 호출 누락이 아니라 "곡 이름 불일치 + 내장 곡 파일 없음".**
1. 전투 화면 V4 는 `UI.scr === 'v4'`. `trackFor`(15044 래퍼)가 `V4.W.siege ? 'siege' : 'field'` 를 돌려주고, 구 전투 화면(`UI.scr==='battle'`)은 10827 판이 `march`/`siege`/`field` 를 돌려준다.
2. 그런데 최종 곡 표 `SONGS`(11313)에는 title·spring·summer·autumn·winter·newyear·**tension·battle** 8곡뿐이라 `field`·`siege`·`march` 가 **없다.** `sndPlay`(11209)와 11347 래퍼가 모르는 이름을 `title` 로 바꾼다 → 전투에서도 느린 표제곡(72bpm)이 흐르거나, 같은 곡이 이어져 "BGM 이 없다"고 느껴진다. 반대로 있는 곡 `battle`(140bpm)·`tension`(100bpm)은 어떤 경로에서도 불리지 않는다(고아).
3. V4 전용 내장 곡 경로 `JSND.bgm('field'|'siege')`(15125)는 `JOJO_BGM`(`<script id="jojo-bgm">`) 이 있어야 동작하는데 커밋본에는 **없다**(문서: "BGM 파일은 커밋본에 없음, CD 오디오"). `bgmData()` 가 null → `e.r='none'` → 합성 BGM 쪽(위 2번)으로 떨어진다.
4. 승패 징글(`endBattleUI` 10728 → `sndJingle`)과 `jbgm('win'/'lose')` 호출(14698~)은 있으나, 승패 곡 데이터도 위와 같이 없다. `startBattle`/`autoBattle` 경로(AI끼리·위임)는 화면이 없어 소리가 없는 것이 정상.
5. 진입 시 호출: 전략→V4 전환 때 `render()`(6726: `BGM.play(trackFor(UI.scr))`)가 불리는지는 경로별로 확인하지 못함(**미확인**). 호출이 있어도 1~2의 이름 불일치로 title 이 된다.

**가장 싼 1차 수정(설계 제안):** `trackFor` 가 `field`·`siege`·`march` 대신 기존 `battle`/`tension` 을 돌려주게 매핑하거나, `SONGS.field`/`siege`/`march` 를 `battle`·`tension` 의 파생으로 등록. 이것만으로도 전투 음악이 나온다(청취 평가는 미확인). 이어서 아래의 본 설계로 확장.

### 전투 BGM 구조 (단계별 곡 = 같은 주제의 층 켜고 끄기)
| 단계 | 시점 | 곡/층 | 템포·악기 |
|---|---|---|---|
| 진입 | 출진 편성·`B.deploy` | `march`: 큰북 행진 장단 + 나각 신호 + 낮은 쟁 | 100bpm, 단조 오음, 24~32마디 루프 |
| 진행 | 평상 교전 | `battle`(야전) / `siege`(농성, 낮은 북 + 징 느린 맥박) | 야전 128~140, 농성 96~104, 북·베이스·비파 트레몰로 + 이호 선율 |
| 클라이맥스 | 병력 비율 <0.5(열세) 또는 아군 총대장 위기, 성문 돌파·적장 격파 직후, 마지막 N턴 | 같은 곡에 **긴장 층 추가**: 템포 +8%, 북 16분 롤, 징 간격 단축, 선율 한 옥타브 위 | 층만 더하므로 곡이 끊기지 않음 |
| 승리/패배 | `endBattleUI` | 기존 `win`/`lose` 징글(8초) 후 평시(계절 곡) 크로스페이드 | 승: 금관 팡파르+징, 패: 이호 하강+종 |

클라이맥스 판정은 `B.units` 병력 합 비율, 성문 상태, 남은 턴으로 **매 턴 한 번**만 계산(박자마다 계산하지 않음). 열세와 우세 모두 층은 켜되, 열세 시 단조 변치음·낮은 북을 강조한다.

### 평시 BGM 과의 크로스페이드
- 평시→전투: 평시 곡 `musicGain` 을 1.0초에 걸쳐 0 으로, 전투 곡을 0.6초 늦게 0→목표로 올림(현행 0.25초 컷+0.61초 대기 대신). 새 곡의 `step` 은 0 에서 시작하고 첫 마디를 북 단독으로 시작해 박자를 맞춘다.
- 전투→평시: 승패 징글을 끝까지 들려준 뒤(징글 중 곡 볼륨 -12dB 더킹) 1.5초 교차. 도중에 종료하면 징글을 건너뛰지 않는다.
- 구현: 곡마다 별도 게인 버스(`songBus`)를 두고 `musicGain` 아래에서 교차(현재는 한 버스를 공유해서 페이드가 곡 전환을 가림).

### 전투 효과음과의 볼륨 균형
- 현행: 음악 `BGM.vol*0.55`, 효과음 `min(1, BGM.vol*1.1+0.2)` → 보통(0.5)에서 음악 0.275 : 효과음 0.75, 비 약 1:2.7. 전투는 효과음이 많아 음악이 묻힌다.
- 제안: 전투 중 음악 게인 x0.8, **사이드체인식 더킹**(큰 효과음 `impact`·`collapse`·`charge`·`tactic` 발생 시 음악 -4dB, 120ms 어택·500ms 릴리즈), 북 위주 음악이 `thud`·`impact` 와 대역(60~160Hz)이 겹치므로 전투 곡의 taiko 에 하이패스 90Hz 를 걸어 둠. 효과음 볼륨 분리(위 (c) 설정)와 같이 진행.
- V4 에서 `JOJO_BGM`(원본 CD 곡)이 있으면 그것이 우선(현행 `JSND` 구조 유지). 공개 배포 시에는 제거 대상이므로 **합성 곡이 기본 동작**이어야 한다 — 이 설계가 바로 그 대체다.

### 구현 순서 추가
0단계(최우선·소규모): `field`/`siege`/`march` → 기존 `battle`/`tension` 연결로 전투 음악 복구, `shot_harness ?audio=1` 의 `__sfxLog` 와 `SND.scene` 로 장면 이름 확인.
이후 (d)의 순서에 합류: 전투 곡 파생 → 클라이맥스 층 → 크로스페이드·더킹. 전투 코드(`V4.*`)는 건드리지 않고 음악 훅만 추가하므로 `battle_sim` 재측정은 "해당 없음".
