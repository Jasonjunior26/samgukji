## 2. 항목 1 — 전투 v4.10 훈련도 위력 계수

**목적**: V4에서 훈련도가 시작 사기(`60 + 훈련/4`)에만 들어가고 피해량에는 안 들어가 훈련이 승패에 영향이 없던 것을 고친다.

**확정 규칙과 수치**
- `dmgJ(a, d, counter)` 끝(`return dmg` 직전)에서 `k = 0.85 + 0.15 × min(100, 훈련)/100`을 곱하고 `Math.max(1, Math.round(dmg * k))`로 돌려준다. 시험기(`tools/battle_train.js`)는 `Math.round`를 썼다.
- 훈련 0 → ×0.85, 100 → ×1.0. 공격·반격(`counter`) 모두 같은 식.
- 훈련은 **그 부대가 속한 쪽 도시**: 공격측(`team(a) === 'A'`)은 `C(W.from).train`, 수비측은 `C(W.to).train`. `mkUnit`이 이미 `(side === 'D' ? C(ctx.to) : C(ctx.from)).train || 50`을 쓰므로 같은 방식(없으면 50)으로 읽는다.
- **책략·일기토·성문 공격(`hitGate`)에는 곱하지 않는다**(문서 결정은 `dmgJ`만).

**근거 문서**: `docs/변화_전투.md` v4.10 (52~78줄), 시험기 `tools/battle_train.js`.

**수정할 html 위치**: `V4.dmgJ` 12259~12270. 성문(S3)과 같은 모듈이지만 서로 다른 함수. 훈련을 읽는 `W.from/W.to`는 `V4.start` 12380에서 설정(12390대). `v4AutoBattle` 13268은 `V4.simulate`를 쓰므로 자동으로 반영된다.

**시험·완료 기준**
- `node tools/battle_train.js 200 0.85` 재현: 공성 공격 40·수비 100에서 공격 승수 55 안팎(오차 ±7), 100 대 40에서 122 안팎, 70 대 70은 계수 없음과 비슷(94~97).
- `node tools/battle_sim.js 20` 기준선과 비교(§10).
- 완료 기준: 훈련 40 대 100 공성에서 훈련 높은 쪽이 확실히 유리, 같은 훈련끼리 승수 불변(오차 안), 오류 없음.

**알려진 문제·미확인**
- 야전은 시험 편성에서 공격이 95%라 훈련 효과를 검증하지 못함(병력 비슷한 편성으로 재검증 필요, 미확인).
- 같은 훈련끼리 전체 피해가 줄어 전투가 길어질 수 있음. 평균 턴 미측정(미확인).
- `winChance`(`V4WIN` 3412)·`v4AutoBattle` 승률 보정이 이 계수를 반영해 재보정이 필요할 수 있음(미확인). 구현 후 `tools/battle_calib.js`를 돌려 `winChance` 맞힘이 크게 나빠지지 않았는지만 확인하고, 나빠졌으면 `V4WIN` 재보정은 **v108로 미루고 문서에 기록**한다.

## 3. 항목 2 — 인연·공적 확정안

## 4. 항목 3 — 성문

**목적**: 야전·공성에서 성벽 틈으로 성 안까지 그냥 들어가는 문제를 없애고 성문 개념(열고 닫기)을 되살린다.

**확정 규칙** (`docs/성문_설계.md` 규칙 1~6 = R1~R5 + AI, 3차 최종 권고 1~5)
- **R1** 성이 있는 지도에는 항상 성문이 있다. 기본 닫힘. 야전·공성의 차이는 시작 배치뿐.
- **R2** 성 안(성곽 상자 `inCastle`)과 밖의 부대끼리는 **원거리 병종(`famOf` 2·4·5)만** 칠 수 있다(양방향 대칭). 근접은 문이 열려야 싸운다. 열린 문(`O`)이 하나라도 있으면 해제(시험기 구현 기준; 성벽 위 칸 구분은 단순화 — 설계는 성벽 위도 "성 안"으로 침).
- **R3** 수비측 부대가 닫힌 문을 지나쳐 그 다음 칸을 고르면 "성벽을 열겠습니까? Y/N". Y면 열고 그대로 이동, N이면 이동 취소. (시험기에는 Y/N UI가 없고 AI가 단계 시작에 문 1개를 여는 것으로 대체 — **플레이어 Y/N은 구현 때 새로 설계**.)
- **R4** 한 번 열린 문은 닫히지 않는다. 열린 문(`O`)과 부서진 문(`부서진문`)은 통과 가능 칸으로 같이 취급.
- **R5** 공격측은 문을 열 수 없다. 충차·투석·정란 등으로 부순다(기존 `hitGate`).
- **수비 AI 열기 기준**: 수비 병력 합 ≥ 공격 병력 합 × **1.3**일 때만 연다. (시험기 openOK는 "공격 원거리가 처음의 절반 이하" "이미 성 밖 수비 부대 있음"도 포함했으나 권고 K2 결론은 **병력비 1.3 단독**이다. 열 문은 한 번에 하나.) 열리면 수비 근접(총대장·원거리 제외)을 돌격 AI로 바꿔 출격 허용.
- **복귀 규칙은 넣지 않는다**(시험상 효과 0).
- **문 없는 공성 지도**: 공성(`siege`)이고 문 칸(`T`)이 0개인 큰 성 지도에만 **자동 문**(성곽 상자 둘레에서 **공격 쪽 변의 한가운데** 성벽 칸 하나를 `T`로) + **둘레 틈 막기**(성곽 둘레의 통행 가능한 비벽 칸을 성벽 `L`로, 내구 포함. 공성 평균 8.0칸). 틈 막기는 자동 문과 함께 넣는다(틈이 있으면 문이 장식).
- **야전의 작은 성 지도(11·16·17·20)에는 자동 문·틈 막기를 적용하지 않는다**(적용 시 공격 승률 −32%p, 턴 2배). 이 지도들은 R1~R5만 적용되며 문 칸이 없으므로 규칙이 걸리지 않는다.
- 열린 문 병목(문칸 점유 17~20%턴, 출구 막힘 27~35%턴)은 허용. 문 2칸 폭은 미시험이라 하지 않는다.

**근거 문서 위치**: `docs/성문_설계.md` 5~12줄(규칙), 13~19(구현 메모), 20~28(AI), 29~60(1차), 61~83(2차 결론 1~4), 3차 "최종 권고" 122~128줄 부근. 시험기 `tools/gate_sim.js`(헤더 3~8줄에 R2~R5 구현 정의), `tools/gate2_sim.js`(자동 문 `mid`/`mid+fill`).

## 6. 항목 5 — 국책·뿌리 (§21 장치)

**목적**: 뿌리 4개(경륜·강병·상략·덕화)를 게임 상태로 만들고, 뿌리마다 "통일하는 자기 방법"을 주는 서명 장치 3개 + 기존 도구 가중 + 용병 계약제를 넣는다. 국책은 지금처럼 매년 1월, 뿌리는 새 게임에서 한 번 고정.

### 7-2. 6a — 물가·예비금 (2층 물가) — 확정
- **물가(세력) = 전국 물가^a × 세력 물가^b**, a=1, **b=0.3**. 전국 = 천하 평균 수입이 시작 때 대비 늘어난 비율의 0.6제곱(v105 `priceIdx()` 6422의 정의), 세력 = 그 세력의 시작 대비 수입 증가분(시험기: 세력 명목 수입 비, 최대 4배로 자름).

### 7-3. 6b — 교역 개편·거점·뿌리 게이트
- **누구나 교역**한다(관문 필수 폐지). 명령은 수도를 포함한 어느 도시에서든 제약 없이(결정 10). 거래 한도 = 세력 단위(시험기: 세력 전체 잉여금(예비금×2+병력 유지비 초과분)의 50%까지, **가정**). 선박 휴식 없음.

## 13. 새 세션 시작 명령

사용자가 새 Opus 세션에 아래 블록을 그대로 붙여 넣는다.

```
/model opus

프로젝트: C:\Users\USER\orca\projects\samgukji (Windows). 사용자는 "빌드하자"고 말했다. 지금부터 v107을 html에 구현한다.

먼저 이 순서로 읽어라 (한 번에 3,000자 이하로 끊어 읽고 samguk_v105.html은 절대 통째로 읽지 마라):
1) CLAUDE.md
2) docs/v107_빌드명세.md  ← 이 작업의 유일한 지시서. 순서(§1)·체크리스트(§9, §10)·롤백(§11)을 그대로 따른다.
3) docs/README.md
4) docs/코드지도.md
항목별 근거 문서는 명세서 각 항목의 "근거 문서" 줄에 있다. 해당 항목을 구현할 때만 그 부분을 줄 범위로 읽어라.

작업 규칙:
- 브랜치 build/v107에서 S0(파일명 samguk_v105.html -> samguk_v107.html 전환, 기준선 측정)부터 시작하고, 항목마다 구현 -> 시험(tools/) -> docs/변화_*.md 맨 위 새 항목 -> docs/코드지도.md 줄 번호 갱신 -> 한국어 커밋 순으로 끝낸다. 커밋 끝에 Co-Authored-By 줄을 붙인다.
- 항목 사이 구현 순서는 명세서 §1 (S0 이름 전환 -> 훈련도 -> 공적 -> 성문 -> 자산 도구 -> 뿌리·국책 -> 교역(6a~6d) -> UI -> 선택 작업).
- 명세서에 "미확인"·"구현 때 확인"으로 적힌 곳은 지어내지 말고 코드를 grep으로 확인한 뒤 결과를 변화 문서에 적어라. 사용자 확정 수치(명세서에 "확정")는 임의로 바꾸지 마라. 바꾸고 싶으면 이유와 함께 먼저 물어라.
- 전투는 각 단계 전후로 node tools/battle_sim.js 20 을 돌려 기준선과 비교해 기록한다. 출력은 파일로 저장해 head/grep으로만 본다.
- 서브에이전트는 모델을 지정하지 않는다. 한 에이전트는 약 100요청 또는 컨텍스트 약 20만 토큰 안에서 끝내고, 넘을 것 같으면 결과·남은 일·핵심 경로를 docs/*.md에 적고 종료하게 한다. 백그라운드 에이전트는 완료 시 한 번만 보고하게 한다. 기계적 작업(파일명 전환, 자산 도구, 문서 정리, 회귀 측정)이 Sonnet에 맞으면 작업 전에 먼저 나에게 알리고 "/model sonnet으로 바꾸세요"를 함께 말해라. 컨텍스트가 10만 토큰을 넘으면 fork 대신 필요한 문맥만 담아 새 에이전트를 띄워라.
- screenshots/ 와 assets/ 는 커밋하지 않는다. 미추적 tools/_orig_sim.js, tools/bond_merit_sim.js, docs/sim/rk_* 도 건드리지 마라.
- <script id="jojo-*"> 블록은 코에이 원본 자료(개인 플레이 전용)다. 공개 배포 시 제거해야 하므로 이번 작업에서 새로 넣는 병종·효과음도 같은 블록 규칙을 따르고, 배포 전 제거 대상임을 변화 문서에 적어라.
- 단계가 끝나면 결론을 docs에 남기고 나에게 /compact 를 권해라.
- 전부 끝나면 최종 보고(구현한 항목, 시험 수치, 미확인 목록, 남긴 항목)를 하고 "/model sonnet 으로 돌아가세요"라고 안내해라. 병합(master 반영)은 내가 확인한 뒤에만 한다.
```

## 14. 이 명세의 한계 (작성자가 확인 못 한 것)

- html은 읽지 않고 `grep -n`·줄 범위로 함수 위치만 확인했다. §3의 공적 지점 8곳, §6의 국책 가중 위치, §7-6의 인구 갱신 유효 정의, §5의 시트 호출 지점은 **미확인**이다.

- v106 본문 수정 약 13곳은 목록만 확인했고, 정예 다중 지정 UI 이식의 세부는 읽지 않았다.
- `.claude/` 설정과 메모리에 파일명이 박혀 있는지는 확인하지 않았다.
- 휴대폰 성능, 청취, 눈으로 보는 지도 가독성은 모두 미확인이다.
