# 교역 친선 메뉴 설계 (2026-10-23, 미빌드 · html 미수정)

`교역_친선_설계.md`(규칙)를 화면과 코드에 옮기는 **구현 지침**이다. 다른 세션이 이 문서와 설계서만 보고 `samguk_v108.html`에 합쳐 빌드할 수 있게 쓴다. 줄 번호는 2026-10-23 grep 기준(빌드 중 밀리므로 항상 `grep -n`으로 다시 찾는다). 확인 못 한 것은 **미확인**.

## 0. 확정 규칙 요약 (설계서 §1~§9, 10-23 확정 반영)
- 교역도를 올리는 길은 **친선 하나**. 나라당 월 1번, 금 또는 군량 지불, 거리 배수(고구려·왜 1.0 / 서역 1.5 / 대진 2.2 / 부상 3.0), 비용 = 기본 60 × 물가 × 거리배수 × (1 + 교역도/50). 상승폭 Δ5×(1+0.5×거점)·감쇠(월 −1, 20 미만 −0.5) 확정.
- 풀: 나라마다 Σ세력 `rel` ≤ K (K=200×max(1.5, n0/12)), 초과분은 다른 세력에서 비례 차감(소수 저장, 표시만 반올림). 세력 단위 추가 제한 없음(AI 포함, 5위 밖 포기 규칙 넣지 않음).
- 보상: 40 이주민 시작 / 60 인재 탐색 단추 + 1등급 / 80 2등급 + 교역 전법 해금 + 이주민 상한 7% / 100 3등급(나라당 1명).
- 이주민: 스톡 `c.imm`, 상한표 V1(40→2%, 60→4%, 80→7%, 100→10%, 선형, 합산 상한 10%), 쌓임 연 2%, **이탈 월 16%**(10% 아래까지 약 13개월), 원래 인구 증가와 별도 계산.
- 교역 전법: 전투당 세력마다 2번, 위력 2단계의 60%, 교역도 ≥80 해금(전투 시작 시점 판정).

## 2. 해외 친선 시트 (나라 카드)
`openWorldTrade`를 `openSheet('해외 친선', …)`로 다시 쓴다. 세로 스크롤 카드 5장(가로 화면에서는 2열). 기존 `btn`(6596)·`trBar`(12113)·`openSheet`(6629) 사용.

```
┌ 해외 친선 ───────────────────────────── [닫기]
│ 이번 달 친선 3/5곳 사용 · 물가 ×1.12 · 지불: (●금 ○군량)
│ 이주민 총 +4.3% (상한 7.0%) · 교역 전법 해금 2곳(고구려·왜)
├──────────────────────────────────────────
│ 고구려  (거리 1, ×1.0)           순위 2위 / 점유 80.0 · 풀 200
│ 교역도 [██████████░░░░░░] 82/100        ← 눈금 40·60·80·100
│ 현재 보상: 이주민 상한 7% · 인재 1·2등급 · 교역 전법 「복병」
│ 다음: 100 → 3등급 인재(최우수 1명) · 상한 10%
│ 경쟁: 1위 ○○ 91 / 3위 △△ 60 …        (상위 3곳 표시)
│ [친선 −금 224]  [인재 탐색 −금 224]       ← 가능하면 활성
├──────────────────────────────────────────
│ 왜 … (같은 형식)  │ 서역 │ 대진 │ 부상
```
- **교역도 바**: 현재값 = `trRel(fid, nat)`(소수는 반올림). 눈금선 40/60/80/100을 `trBar`를 확장해 얹는다.
- **세력 점유 순위**: 나라별 `T.rel[*][nat]` 전 세력 합·정렬(87세력이므로 월 1회 캐시 `T.rank[nat]` 권장, 열 때 직접 정렬해도 비용 작음). 풀 `합계/200`은 상단 또는 카드에 표시.
- **현재 보상 단계**: 함수 `trTierOf(rel)` 신설 → 0/40/60/80/100 구간 문자열. 다음 문턱 표시.
- 나라 카드 5개: `TR_NAT` 키 5개(kor·jpn·eeu·weu·usa)가 고구려·왜·서역·대진·부상에 대응하는 것으로 `TR_HAT`(11963)에서 보이나, **키↔나라 이름 대응은 `TR_NAT` 본문 11951~11957에서 확인(미확인)**.
- 내가 깎였을 때: 카드에 `▼ 지난달 −2.4 (○○이 올림)` 한 줄(월 갱신에서 `T.lastDrop[fid][nat]` 기록).

## 3. 친선 시트
`openTrBanq`(12160)를 개조. 장수 선택(`trGenList` 12124)은 유지하되 **친선은 군주 포함 자유 장수 중 1명이 사절**(기존 `trBanq`가 `g.acted` 사용: 12353). 

```
┌ 고구려 · 친선 ───────────────────────
│ 사절: [장수 선택 ▼] (매력 78)
│ 지불: (●금 ○군량)
│ 비용 계산
│   기본 60 × 물가 1.12 × 거리 1.0 × (1+교역도 82/50=2.64) = 금 591
│   군량 환산: 591 ÷ 군량값 20 = 군량 ?  (도시 창고 출처: 여유 큰 도시부터)
│ 거리 배수: 고구려 ×1.0  (서역 ×1.5 · 대진 ×2.2 · 부상 ×3.0)
│ 이번 달 이 나라 친선: 미사용 (월 1회)     ← 사용했으면 "이미 보냈다. 다음 달에" 비활성
│ 예상 교역도: +N (거점 ×1.5 포함) → 83.x   (상승폭 시험값)
│ 풀 영향: 합계 197 → 200 초과 3.0 → 다른 세력에서 차감
│ [친선 보내기]  [취소]
└──────────────
```
- 함수: `trBanq`(12353) 본문을 **`trFriend(fid, nat, gn, payKind)`** 로 교체. 순서: 월 1회 검사(`T.fr[fid][nat] === trYm()`이면 거부) → 비용 계산 `frCost(fid, nat)` → 지불(금: `trPay` 12307 재사용, 월 한도 `noLimit` 인자 `true`로 호출 — 금 월한도 `trBudget` 12302 개념은 폐지 후보이므로 **한도 없이 지불**; 군량: 신설 `frPayFood`) → 상승 `trGain`(12052의 `gainMul` 두 줄 제거, 거점 증폭 `trAmp` 유지) → 풀 정규화 `trPoolFix(nat, exceptFid)`.
- 군량 지불: 도시 창고(`c.food`·`c.rice` 등 **필드명 미확인**, grep으로 `foodPrice` 정의를 먼저 확인) 가운데 군량 개월분 하한을 지키며 여유가 큰 도시에서 차례로 뺀다(설계서 §3 해당 문장).
- 월 1회: 신설 `T.fr = { [fid]: { [nat]: ym } }`. ym은 `trYm()`(12301).
- 거리 배수: 신설 상수 `TR_DIST = { kor:1, jpn:1, ...서역:1.5, ...대진:2.2, usa:3 }`(키 매핑은 TR_NAT 확인 후).
- 표시: 위 목업의 계산 줄을 `frCost` 반환 객체 `{base, price, dist, relF, gold, food}`로 그대로 출력.

## 4. 인재 탐색 시트
조건: 그 나라 `trRel ≥ 60`일 때만 카드에 단추가 보인다(60 미만 숨김, 회색 아님).
```
┌ 고구려 · 인재 탐색 ───────────────────
│ 교역도 82 → 후보 등급: ◉1등급(6명 중 미발견 4) ◉2등급(5명 중 미발견 5) ○3등급(교역도 100 필요)
│ 한 번에 열린 등급 중 미발견자 1명을 무작위로 만난다 (같은 인물은 한 번만 나타남)
│ 지불: (●금 ○군량)  비용 금 591 (친선과 같은 배수) · 월 1회
│ 이번 달 이 나라 인재 탐색: 미사용
│ [탐색]  [취소]
```
- 후보 풀: `Object.values(S.gen).filter(g => g.nat === nat && g.st === '미등장' && !g.found && g.trTier <= openTier(rel))`. `openTier`: 60→1, 80→2, 100→3(`TR_TIER` 11959 재사용).
- 유일성(설계서 §5-1): 선택 즉시 `g.found = true; g.st`를 일반 재야 상태로 바꾸는 한 함수 `trTalent(fid, nat, payKind)`에서 처리(기존 `trCheck` 12058이 발견 로직을 가지므로 거기서 추출·재사용). 같은 달 AI 처리는 순차 한 명씩. 일반 재야 탐색 `cmdSearch`(738)에서 `origin === '교역'` 제외 추가. `trInit`(11990)은 이름이 이미 있으면 안 만든다(현행 유지, 11996).
- 월 1회: `T.tal = { [fid]: { [nat]: ym } }`.
- 후보가 없으면(전원 발견) 단추 비활성, 사유 `이 등급의 인재는 모두 나타났다`.
- 무엇이 등급별로 몇 명인지: `TR_GENS`의 `tier` 인자(11996 구조분해: `[nat, tier, n, …]`)를 센다. 60명 확장(설계서 §6-4 1번)은 **별도 단계**.

## 6. 이주민 현황 표시
- 해외 친선 시트 상단 요약(§2 목업): `이주민 총 +x.x% (상한 y.y%)`. x = Σ`c.imm`/Σ(`c.pop`−`c.imm`) (내 도시), y = 합산 cap(최대 10%).
- 도시 상세: `이주민 ${fmt(c.imm)}명(${주된 출신국})` — 도시 상세 렌더는 `render` 래퍼(12112) 주변. **주된 출신국 기록은 `c.immNat`(신설)이 필요한데, 단순화하려면 "교역 이주민"으로만 표기하고 출신국은 생략**(권장, 설계서의 '○○ 계'는 보류).
- 상한 계산 `immCap(fid)`: 나라별 `trRel`을 구간표로 환산해 합산 후 min(0.10). `monthlyPop`(5063)의 `c.pop` 갱신은 **원 인구만**(`pop−imm`)에 적용되게 수정: `const base = c.pop − (c.imm||0)`로 gap 계산하고 이주민 변화는 별도 단계 `monthlyImm()`에서 처리. `monthlyPop`이 이 식을 쓰는 다른 래퍼(13439 주석의 덕화 회복 등)와 겹치는지는 **빌드 때 `monthlyPop` 래퍼를 grep해 확인(미확인)**.
- 이탈: `imm > base×cap`이면 초과분 × 0.16이 `pop`·`imm`에서 동시 감소.
- 점령·상실: `imm`은 도시에 남는다(따로 코드 불필요, 새 주인 cap으로 다음 달부터 계산).

### 8-3. 구버전 세이브 마이그레이션 (`trInit` 11990 + `postLoad` 래퍼 12005에서)
- 없는 필드는 기본값: `T.fr/T.tal/T.lastDrop = {}`, 모든 `c.imm = 0`(`c.imm == null`이면 0).
- 폐지 필드는 읽지 않고 **무시**(삭제하지 않아도 됨, 용량이 신경 쓰이면 `delete T.mk; T.convoys=[]; T.study=[]; T.unit={}; T.bud`는 보류 후 `c.cargo`는 **화물을 금으로 환산해 도시 금에 합산**할 것인지 결정 필요 → 사용자 확인 필요(미확인))).
- `T.rel` 풀 초과 보정: 로드 직후 나라마다 합 > 200이면 `trPoolFix`로 한 번 정규화.
- 인구: 옛 세이브의 `pop`은 그대로 원 인구로 간주(`imm=0`).
- 진행 중이던 호송(`T.convoys`)의 화물은 환수 처리(금 환산 또는 소멸)를 정해야 한다 — **미확정**.

## 9. 월 보고 / 로그 문구 (`news()` 536 사용)
- 친선 성공: `○○이(가) 고구려에 친선 사절을 보냈다 — 교역도 82 → 84 (금 591)`.
- 풀에 밀림(플레이어만): `△△이(가) 왜와 가까워져 우리 교역도가 줄었다 (60 → 57)`.
- 자연 감쇠(요약): `이달 교역도 감소: 고구려 −1, 왜 −1`.
- 보상 단계 변화: `고구려와의 교역도가 60에 이르러 인재 탐색이 열렸다` / `… 80 미만으로 떨어져 교역 전법을 쓸 수 없다`.
- 이주민: `이주민 +0.3%p (상한 7.0%)`, 상한이 내려갈 때 `교역도가 줄어 이주민이 돌아가기 시작했다`.
- 인재 발견은 §5, 전투는 §7.

## 10. 빌드 순서 체크리스트 (작은 단계, 각 단계 뒤 확인)
공통: 시작 전 `node tools/...` 월 해시 기준선 확인(기존 월 해시 도구·회귀 명령은 `docs/README.md`·최근 커밋 `660688f` 메시지의 `regress`에서 찾는다 — **정확한 명령은 미확인**). 각 단계 끝에 `node tools/bump_build.js`, 문서(`docs/변화_*.md` 맨 위 항목)·`docs/코드지도.md` 갱신, 커밋. "빌드하자" 지시 후에만 시작.

1. **F0 폐지 정리(상거래·시세·수송·학습)**: 시트·ACT·월 갱신에서 시세 감쇠/호송/학습 완료 제거, 창고 화물 정리. 확인: 월 해시 **변한다**(교역 금 흐름이 없어지므로) — 변화 폭을 기록. `trMonthly`·`trAiMonthly`가 예외 없이 도는지 100개월 스모크.
2. **F1 풀 K=200 + 감쇠**: `trGain`에서 배율 제거, `trPoolFix`, 월 감쇠. 확인: 어떤 달에도 Σrel ≤ 200+ε, 감쇠 후 음수 없음. 월 해시 변화 기록.
3. **F2 친선 명령 + 월 1회 + 금/군량 + 거리배수**: `trFriend`, 새 시트(§2·§3). 확인: 같은 달 두 번째 거부, 군량 지불 시 창고 감소량 = 환산식, 세이브·로드 후 `T.fr` 유지.
4. **F3 AI 친선**: `trAiMonthly`를 친선만으로. 추가 제한 없음. 확인: 시험(`docs/교역_친선_설계.md` §10-7 방식) 점유 분포가 시뮬 결과와 큰 차이가 없는지, 월 해시 변화 기록.
5. **F4 이주민**: `monthlyPop` 분리, `c.imm`, cap V1, 이탈 월 16%, 표시. 확인: 교역도 0 강제 시 10% 아래 약 13개월(계산값 13.2), `pop`이 `popMax` 초과 안 함, 옛 세이브 로드 후 `imm=0`.
6. **F5 인재 탐색 + 팝업 + 유일성**: `trTalent`, `cmdSearch` 제외, 점검 스크립트(60명 이름 고유, 발견 후 `S.gen` 개수 불변). 확인: 월 해시 변화(AI 포함 시) 기록.
7. **F6 인재 60명 확장 + `TAC_U` 행**(설계서 §6-4 1~3). 확인: `TAC_U` 이름 ↔ `S.gen` 일치 스크립트.
8. **F7 교역 전법**: `B.trad`, 단추, `tacUse` 옵션, AI. 확인: 균형 문서 결과 반영, `tools/battle_sim.js 20`은 V4 경로를 건드릴 때만(보통 해당 없음).
9. **F8 마이그레이션·최종 회귀**: 옛 세이브 몇 개 로드, 월 해시 8종 비교, 문서 최종 갱신.

단계 사이에 임시로 깨지는 화면이 없도록, F0에서 진입 메뉴를 먼저 새 시트(F2 내용 비어도)로 바꾸지 않고 **F2와 함께** 바꾸는 편이 안전하다(F0~F1 동안은 옛 시트에서 친교만 쓰이게 두는 안도 가능 — 선택).
