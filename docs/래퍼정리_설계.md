## 1. 읽는 법 (래퍼 실행 순서 규칙)

1. `{ const f = X; X = function(){ A; f.apply(); B } }`가 여러 겹이면 **뒤 줄 래퍼가 바깥**이다. 전처리 A는 **뒤 줄 → 앞 줄** 순서로 돌고, 본체가 돈 뒤 후처리 B는 **앞 줄 → 뒤 줄** 순서로 돈다. 아래 표는 소스 순서(= 후처리 순서)로 쓰고, 전처리 순서는 따로 적었다.
2. **호이스팅**: 같은 `<script>` 블록 안에서 같은 이름의 `function` 선언이 여러 번 나오면 **마지막 선언**이 블록 실행 전에 이미 묶인다. 그래서 그 선언보다 앞줄에 있는 `const f = X`도 마지막 선언을 잡는다(`cmdTrain` 4622 → 5100). 앞쪽 선언은 모두 죽는다.
3. **블록 경계**: 메인 블록은 375~10858이고, 그 뒤로 `<script>`가 40여 개 있다. 뒤 블록에 같은 이름의 `function` 선언이 있으면, 그 블록이 실행될 때 앞 래퍼 체인을 통째로 덮는다. 대상 9개 함수의 선언은 모두 메인 블록에 있어 이 문제는 없다(확인, 정적). 뒤 블록에 있는 것은 래퍼뿐이다.
4. **통째 재할당**: `X = function(){…}`나 `X = Y;`처럼 앞 값을 잡지 않고 바꾸면 앞의 선언과 래퍼가 모두 죽는다(`cmdReward = cmdRewardV15` 4018, `openDraft = function` 13798).
5. **문맥 전역 플래그**(래퍼가 서로 신호를 주고받는 통로):

## 4. 목표 구조

### 4.1 `monthlyUpdate` → 단계 배열 `MONTH_STEPS`

```js
// 본체 1118의 이름만 monthlyCore 로 바꾼다(내용 그대로).
const MONTH_STEPS = [];                 // 1118 바로 뒤(첫 래퍼 3294보다 앞)에 둔다
function monthStep(id, o) { MONTH_STEPS.push(Object.assign({ id }, o)); }  // o: { pre?, post?, fin? }
function monthlyUpdate() {
  const S_ = MONTH_STEPS, tok = new Array(S_.length), ran = new Array(S_.length).fill(false), fined = new Array(S_.length).fill(false);
  let r;
  try {
    for (let i = S_.length - 1; i >= 0; i--) { ran[i] = true; if (S_[i].pre) tok[i] = S_[i].pre(); }   // 바깥(뒤) → 안(앞)
    r = monthlyCore();
    for (let i = 0; i < S_.length; i++) { const s = S_[i]; if (s.fin) { fined[i] = true; s.fin(tok[i]); } if (s.post) s.post(tok[i]); }  // 안 → 바깥
  } finally { for (let i = 0; i < S_.length; i++) if (ran[i] && !fined[i] && S_[i].fin) S_[i].fin(tok[i]); }
  return r;
}
```

- 각 래퍼를 `monthStep('이름', { pre: () => 스냅값, post: tok => … })`로 옮긴다. **본문은 글자 그대로 옮기고, 각 겹의 `try/catch`도 그 겹 안에 그대로 둔다.** 그래야 예외 전파가 지금과 같다(겹이 예외를 던지면 그 뒤 단계가 모두 건너뛰어짐).
- `fin`은 13061처럼 `finally`로 복원하는 겹에만 쓴다(`g.ui` 복원). 13061 후처리의 맨 앞에서 복원하고, 예외가 나도 복원한다.
- **변환은 반드시 소스 순서대로, 첫 래퍼(3294)부터 연속으로 한다.** 러너는 본체 자리에 있다. 아직 안 바꾼 래퍼는 러너 바깥을 감싸므로, 앞에서부터 차례로 바꾸면 순서가 그대로 유지된다. 가운데 겹을 먼저 바꾸면 그 겹이 앞 래퍼들 안쪽으로 들어가 순서가 바뀐다.
- 뒤 블록(10859 이후)의 래퍼도 같은 `monthStep(...)` 호출로 바꾼다. 블록이 실행되는 순서가 등록 순서가 된다. `MONTH_STEPS`는 메인 블록의 `const`라 뒤 블록에서도 보인다.
- 최종 단계 목록에는 `id`를 `'tickMoves'`·`'upkeep'`·`'policy'`처럼 붙이고, 주석에 원래 줄과 버전을 남긴다. 단계 표(§2.1)가 곧 목록이다.
